# Learning V1 · 实施方案

**日期**：2026-10-11 · **状态**：实施中（第一阶段）。上游：[Learning PRD](../product-requirements/prd/prd-10-learning.md)、[来源审查](../product-requirements/research/learning-source-audit-2026-10-11.md)。

## 落地原则

保留 Keybr Guided 与 KTouch 的各自行为；共用输入展示、键盘提示、记录容器等适合共用的部分，不强行合并课程顺序或能力判断。直接复用已授权选择的 Keybr 原代码，保留许可证与来源版本。对来源的严重缺陷只作有证据的最小修复。

第一阶段先交付可执行的来源检查与进度基础，不把未接入原核心的页面包装成可用学习功能。功能完成应以 TP-403–406 的证据为准。

## TP-403 的具体接入方法

1. 读取 Keybr 锁定版本 Guided 的真实入口，递归收集运行依赖及测试；确认词库/音系模型加载路径和来源。
2. 原代码放在单独的第三方目录，记录原路径、SHA-256、许可证与导入版本。仅调整包路径/构建适配；任何改变算法结果的差异进入 LS 记录。
3. 封装很薄的项目适配层：输入已完成有效结果，读取下一轮内容/目标键/可用键；不重写 confidence、平滑、样本过滤或字符选择。
4. UI 只消费适配结果；开始计时、退格、暂停和错误归属保留原语义。现有 TestSession 不作为学习引擎复用。
5. 保留默认参数；界面可暂不暴露高级配置，但不能改变默认语义。未来增加设置另行提出需求。
6. 固定测试轨迹与随机源验证初始化、目标键、新键解锁、薄弱键、低样本、重复完成、暂停恢复；通过后才称为已接入 Keybr。

## TP-404 的内容处理方法

原始素材保持不可变，转换产物保留 course ID、lesson ID、source revision 与 content revision。原课次顺序、课文、大小写、换行等行为均有映射说明。内容校验只报错，不自动生成替换课文。

当前 US 与 GB 候选均有已验证问题。先检查适用完整来源；如必须修复已发现的问题，记录每处原字符范围、错误原因、最小修复、哈希及复核。不得借修复重新设计整套课程或无依据改成短课。数字与标点不在已核查 15 课中，页面范围必须如实说明。

## TP-402 数据实施

- 使用 `typing-performance:learning:v1:guided` / `typing-performance:learning:v1:course` 两个键，和测试结果存储隔离。
- 第一阶段实现存储信封：结构版本、模式、规则/内容版本、布局、引擎原生 JSON 状态。各引擎提供状态验证器，存储层不解释掌握度、不截断原算法所需历史。
- 原算法统计只在客户端；不新增账号/DB/API，不引入遥测逐键上传。
- 读取区分空记录、成功、损坏、未知版本、不可用；写入必须持有读取时的版本标记，避免旧标签页覆盖新状态。浏览器有 Web Locks 时由适配层串行化读改写；无锁环境检测冲突并提示重新读取，不承诺仅凭 localStorage 检查能实现原子事务。
- 清除整个学习命名空间前由 UI 确认；保留测试历史。存储不可用时内存可继续，显示保存失败。

## 上线与回退

学习入口只有在对应真实模块可用后加入导航；来源审查未通过的内容不打包进公开页面。部署/发布源码仓库属于外部操作，不在本轮自动执行。交付源码可采用版本化下载包或另行授权的公开仓库；必须包含我们实际修改的对应源码和必要构建材料，不能只链接上游。

保留原测速路由和数据。学习出问题时可下线学习入口，保留本机学习进度供兼容版本恢复。已有生产审批、域名及分析配置要求继续适用。
