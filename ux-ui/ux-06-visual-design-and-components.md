# 06 视觉风格与控件规范

**版本**：1.1 · **来源**：[用户提供的 736 × 1308 参考图](./assets/reference-visual-2026-10-01.png)（2026-10-01）· **适用**：Typing Performance P0 页面与组件。此文档从参考图抽离设计语言；图中的学校品牌、俄文文案、宇航员肖像与作品图不属于本产品素材。

## 06.1 风格画像

关键词：**太空感、实验性排版、强对比、票券切口、模块化、轻微玩味**。画面由淡紫色大背景托起近黑色网站主体，黑色中嵌入白色内容区；荧光绿只用于即时动作、进度和选中态。大标题以极轻和极重的字重交替，数字被放大成为视觉锚点。黑白/灰阶的立体图像让鲜艳颜色承担引导功能。

页面不是均匀的卡片网格。桌面版有大块黑色舞台、白色异形内容舱、横向排列的倾斜票券；移动版保留黑白紫绿关系，票券变为可横向滚动的序列。参考图的斜向文字带是品牌展示元素，仅用于首页/内容页，不覆盖测试输入区。

## 06.2 颜色系统

下表根据参考图的代表像素提取并换算为 OKLCH；受压缩、阴影和屏幕显示影响，数值为视觉基准，最终在浏览器中微调。原有琥珀/深青 token 已被本规范替代。

| 角色 | 参考近似值 | 产品用途 | 文字配色 |
|---|---|---|---|
| Lavender canvas | `oklch(0.727 0.115 283)` | 页面外部背景、大段品牌过渡、次级 CTA | 近黑 |
| Near-black stage | `oklch(0.231 0 0)` | 主页面壳、测试区外围、深色内容区 | 白 |
| White chamber | `oklch(0.982 0 0)` | 导航、主测试面板、结果浮层、说明区 | 近黑 |
| Signal green | `oklch(0.844 0.223 144)` | 主 CTA、当前选项、进度、高价值提示 | 近黑 |
| Soft lilac control | `oklch(0.688 0.121 286)` | 次级 CTA、轻量选中背景 | 近黑 |
| Charcoal surface | `oklch(0.317 0 0)` | 作品/示例容器、深色内层 | 白 |

```css
:root {

  --tp-stage: oklch(0.231 0 0);
  --tp-surface: oklch(0.317 0 0);
  --tp-chamber: oklch(0.982 0 0);
  --tp-signal: oklch(0.844 0.223 144);
  --tp-lilac-control: oklch(0.688 0.121 286);
  --tp-ink: oklch(0.231 0 0);
  --tp-text-on-dark: oklch(0.982 0 0);
  --tp-text-muted-on-light: oklch(0.410 0 0);
  --tp-text-muted-on-dark: oklch(0.785 0 0);
  --tp-focus: oklch(0.630 0.180 283);
  --tp-error: oklch(0.540 0.190 28);
}
```

**使用比例**：品牌/首页可使用大面积紫色背景和黑色主体，白色承载文字与交互，绿仅在少数高优先级元素出现。测试 Running 状态以黑底白色测试舱为主，不持续显示绿色斜带、3D 装饰或高频动画。参考图的荧光绿和淡紫按钮若配白色小字对比不足；绿色及淡紫填充控件统一使用近黑文字。关键文字必须达到 WCAG AA 对比度，装饰性配色不能承载唯一状态信息。

## 06.3 字体与排版

参考图只能判断**字形气质**，不能可靠识别原字体文件：它属于现代无衬线/几何 grotesk，字面较宽，主标题出现 300 与 800/900 字重强烈切换；数字、序号、短标签偏重。实施建议采用一套可变字体 `Inter Tight`（经许可自托管）作为可替代选型；缺字或加载失败时回退系统无衬线。不要声称它就是参考图原字体。

```css
:root {
  --tp-font-ui: "Inter Tight", "Arial", sans-serif;
  --tp-font-test: "Inter Tight", "Arial", sans-serif;
  --tp-leading-display: 0.96;
  --tp-leading-body: 1.50;
  --tp-tracking-display: -0.025em;
}
```

| 层级 | 桌面 / 移动 | 字重与形式 | 用途 |
|---|---|---|---|
| Display | 64–88 / 40–52px | 300 为主，局部 800–900；紧凑行高 | 首页主题句、结果大数字 |
| Section heading | 40–52 / 32–40px | 300 与 800 混排 | “Your / Typing Performance”类标题 |
| Module number | 32–44 / 28–36px | 900 | `01`、时长、WPM 数字锚点 |
| UI heading | 22–28 / 20–24px | 700–800 | 白色浮层、小节标题 |
| Body | 16–18 / 16px | 400–500，行高约 1.5 | 说明、FAQ、结果解释 |
| Label / button | 13–15 / 14–16px | 700–800 | 控件文字、时间标签；不要照搬图中过小的字 |

标题可用少量全大写和轻重混排，但长篇正文使用正常大小写。英文字母保持清晰可读；标题字距不小于 `-0.04em`。测试文本不使用展示级细字重：建议 22–28px、500–600，字符间距稳定，以阅读和错误定位为先。

## 06.4 形态与布局

- **主框架**：紫色画布中放置近黑色舞台，桌面最大内容宽约 1200–1280px；黑色舞台可以有明确的大圆角或几何切角。移动端贴近屏幕边缘，保留至少 16px 安全边距。
- **白色内容舱**：承载测试、结果和解释，圆角建议 16–24px。可选单侧内凹切口作为品牌特征，但不得侵入正文、按钮或焦点轮廓。
- **票券/站点卡**：短而窄的白色卡片，序号粗黑；选中卡荧光绿。营销区可轻微倾斜和交叠，实际选择控件保持清楚的点击边界和可见焦点。
- **斜向讯息带**：绿色或紫色长条横穿展示区，可重复短语；只在营销页用于品牌节奏，不能作为必须阅读的内容。
- **图像**：灰阶、雕塑感、立体材质与柔和高光。Typing Performance 可用手、键帽、键盘局部或抽象打字轨迹来延续气质；不直接复用宇航员、学校标志及作品图。
- **层级**：黑色大面积承载结构，白色浮层承载可读信息；不依靠大阴影堆叠层级。控件圆角统一，避免每个元素都做不同的异形。

## 06.5 控件库

| 控件 | 参考图形态 | 本产品规格 | 状态要求 |
|---|---|---|---|
| `BrandNav` | 白色胶囊导航、黑色票孔 | 仅首页/内容页使用票孔装饰；测试 Running 时精简导航 | default、hover、focus、mobile menu |
| `PrimaryButton` | 荧光绿横向胶囊 | Start / Retest / 查看结果；近黑字、最小高 44px | default、hover、pressed、focus、disabled、loading |
| `SecondaryButton` | 淡紫胶囊 | 查看解释、切换时长等次要动作；近黑字 | 同上 |
| `DurationSelector` | 倾斜站点卡与高亮卡 | Ready 状态可选 1/3/5；选中绿，未选白；移动横滚 | selected、unselected、focus、disabled |
| `TestShell` | 黑色舞台中的白色主舱 | 文本、输入目标、计时与进度，保持干净 | ready、countdown、running、completed、abandoned |
| `TextRenderer` | 高对比黑白排版 | 当前字符用光标/底色，正确/错误用语义色加形状提示 | current、correct、incorrect、corrected |
| `ProgressTrack` | 黑底细线、绿填充、白色圆钮 | 测试进度可视化；圆钮只显示当前位置，不暗示可拖动 | 0–100%、paused/hidden、completed |
| `MetricDisplay` | 超粗数字 + 细字标题 | 结果首屏优先 WPM，其余指标紧凑排列 | normal、unavailable、warning |
| `ResultCard` | 黑底上的白色异形浮层 | 成绩解释、重测与下一步；内含 `MetricDisplay`，手机宽度内自然换行 | complete、empty、storage warning |
| `HistoryItem` | 深色作品卡 | 最近成绩摘要；固定信息顺序：日期/时长/WPM/准确率 | default、focus、clear confirm |

交互控件保持标准语义：按钮仍是按钮，选择器仍是单选；票孔、倾斜、切角仅是可移除的视觉层。所有状态使用同一种按钮、焦点、禁用和错误词汇。焦点环在紫、绿、白、黑底上都必须清晰；必要时用内外双层轮廓。控件过渡 150–220ms，仅反馈状态变化；`prefers-reduced-motion` 下立即切换。

## 06.6 页面应用

| 页面 | 视觉结构 | 控制重点 |
|---|---|---|
| P-TEST Ready | 紫色画布 + 黑色框架 + 白色测试舱；上方有简化票券时长选择 | 绿色 Start 明确唯一主操作 |
| P-TEST Running | 黑色框架 + 高可读白色输入区；装饰降到最低 | 字符状态、剩余时间、结束动作 |
| P-RESULT | 黑色背景中的白色浮层；WPM 数字为锚点；绿色 Retest | 解释与重测能在首屏看到 |
| P-BENCHMARK | 紫/黑大区块 + 白色内容区，细字与粗体数字混排 | 内容引用、测试 CTA、FAQ 可读 |
| P-HISTORY | 深色区中的简洁成绩行，不用倾斜票券承载表格数据 | 本地性和清除操作清晰 |

## 06.7 交接与验收

1. 在 375px、768px、1280px 检查黑白紫绿结构、按钮触控目标、标题换行与内容区留白。
2. 用实际英文产品文案验收排版，不能只用参考图短俄文；混排标题必须避免单词截断。
3. 检查按钮/正文对比：近黑对白约 16:1，近黑对绿约 11:1，近黑对淡紫约 5.9:1；参考图的白字对淡紫约 2.7:1，不沿用。
4. 对照 [页面线框](./ux-04-pages-and-wireframes.md) 与 [交互状态](./ux-05-interaction-and-states.md)，确保视觉处理没有改变 UJ-01–05 的任务路径。
5. 需在开始前端实现时制作 P-TEST Ready/Running、P-RESULT、P-BENCHMARK 的实际浏览器画面，再以本规范进行视觉验收；图像素材和最终字体文件的许可在使用前核对。
